# Catatan untuk agen

- Stack: Vite + React (empat bagian: `index.html` untuk QR rumah, `petugas/index.html`, `admin/index.html`, `landing/index.html`), API Hono sebagai Vercel Function (`src/server/vercel.ts`, dibundel `scripts/build-vercel.ts` ke `.vercel/output`), database Postgres (Supabase; PGlite saat dev dan tes) lewat Drizzle. Lihat README.
- URL dipetakan di `src/lib/app-paths.ts` dan `scripts/app-routing.ts`: app warga/petugas di root `app.clusternatura.com/` (dev/preview `/app`), dashboard di `app.clusternatura.com/dashboard` (dev `/admin`). Beranda adalah halaman awal dan menu pertama app, wajib login nama/PIN; Ronda production ada di `/ronda` dan Jadwal di `/jadwal`. Alamat lama `/app`, `/petugas`, dan Info warga dialihkan ke root app; subhalaman `/app/*` dan `/petugas/*` kehilangan prefix tersebut. Dev/preview tetap memakai `/app` (Ronda `/app/ronda`). Manifest PWA dan shell offline production memakai root. QR rumah tetap publik di `clusternatura.com/info/r/<token>` (dev `/r/<token>`). Pakai `adminPath`, `petugasPath`, dan `wargaPath` untuk navigasi. Pengelolaan akun ada di tab Akun pada `/dashboard/warga?tab=akun`; `/dashboard/petugas` mengalihkannya ke sana. Penugasan ronda hanya dikelola di Jadwal ronda. Pergantian antara app, dashboard, dan halaman QR harus memuat HTML baru.
- Versi paket lebih baru dari data latih (Vite 8 dengan Rolldown, React Router 8, Hono 4, @hono/node-server 2, PGlite 0.5). Baca tipe/dokumentasi di `node_modules` sebelum memakai API yang belum dikenal.
- Beberapa query yang harus berhasil bersama: `runBatch(db, (tx) => [...])` dari `src/server/db.ts` (satu transaksi). Query harus dibuat dari `tx`, bukan `db`. Supabase lewat Transaction pooler dengan driver `pg`; jangan kembali ke postgres.js (query-nya menggantung di pooler, lihat `src/server/db.ts`).
- `bun run dev` memakai PGlite di `.data/pglite` yang hanya boleh dibuka satu proses. Selama server dev hidup, `bun run seed` dijalankan di proses server itu (endpoint dev `/__dev/seed`, lihat `scripts/dev-server-info.ts`); skrip lain yang membuka PGlite sendiri ditolak oleh penanda `.data/pglite.pid`. Jangan menyentuh `.data/` atau database Supabase tanpa diminta.
- Data satu sumber: satu profil `residents` per orang. Warga tanpa akun menyimpan nama dan `house_id` di profil; warga dengan akun hanya menyimpan `user_id`, nama/rumah diambil dari akun (CHECK). `houseName` memakai akun penghuni, lalu warga pertama; `houses.owner_name` hanya fallback format impor lama dan dipindahkan lewat `adoptLegacyResidents`. Penugasan `ronda_schedule` menunjuk `resident_id`; `house_id` atau `name` hanya penanda jadwal lama yang orangnya belum dipilih (CHECK tepat satu sumber). `userId` pada DTO jadwal dibaca lewat profil, bukan disimpan di jadwal. Membuat akun, pindah rumah, atau impor tidak mewariskan tugas dari rumah. Jangan menyalin nama/blok/nomor ke tabel lain.
- Ekspresi `sql` Drizzle di query satu tabel menulis kolom tanpa nama tabel; di subquery berkorelasi tulis nama tabelnya sendiri.
- Rute API dipasang di `src/server/app.ts`. Sub-app yang dipasang di "/" jangan memakai `.use()` (ikut mengenai rute lain); pasang middleware per rute.
- Pakai Bun sebagai package manager (`bun install`, `bun run …`, `bunx …`), bukan npm. Tes lewat `bun run test` (Vitest), bukan `bun test`.
- Tes: `bun run test` (tes API memakai PGlite di memori, lihat `test/helpers/db.ts`; `TEST_DATABASE_URL` untuk Postgres sungguhan), `bun run lint`, `bun run typecheck`.
- Commit langsung di `main`, pesan mengikuti Conventional Commits, tanpa atribusi.
